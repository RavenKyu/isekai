# 검증한 경로 해석 결과를 그대로 사용한다

## What happened
- 편집기 Load가 입력 symlink를 canonicalize한 뒤 공통 검사 함수가 같은 입력을 다시 canonicalize했다. 검사는 두 번째 경로를 확인했지만 Load는 첫 번째 경로를 열었다.
- 두 호출 사이에 symlink가 바뀌면 검사한 파일과 여는 파일이 달라질 수 있었다.

## Why
- 검사 함수를 Result<()>로 설계해 검증한 실제 경로를 버렸다. 호출자가 따로 얻은 경로를 사용해도 타입이나 일반적인 고정 fixture 테스트로 구별되지 않았다.

## Do this instead
- 경로 검사 함수는 검증한 canonical 경로를 반환하고 호출자는 그 결과를 그대로 사용한다. 검증을 위해 얻은 경로와 열기 위해 얻은 경로를 따로 해석하지 않는다.
- 공통 API의 반환 경로가 상대 경로에서 절대 경로로 바뀌면 모든 호출부의 부모·파일 이름 비교도 살핀다. 경로 표현 변경으로 기존 디렉터리 규칙을 완화하거나 정상 경로를 거부하지 않는다.
- 입력 alias를 바꾼 뒤에도 반환한 경로가 검증한 대상을 읽는지 검사하고, 입력 alias를 그대로 반환하는 변이가 실패하는지 확인한다.
- canonical 경로를 반환하는 검사는 파일 핸들 기반의 완전한 TOCTOU 방지가 아니다. 검증 뒤 실제 대상 자체를 교체하는 경우까지 검증했다고 보고하지 않는다.
