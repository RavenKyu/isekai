# 새 UI를 붙일 때 라이브러리의 기본 파일 출력 경로를 확인한다

## What happened
- 개발용 Demo 창을 추가하면서 ini 저장만 껐다. 라이브러리의 기본 로그 파일 이름은 남아 있어 Demo의 Log To File 버튼이 checkout에 파일을 만들 수 있었다.
- 디스크에 저장하지 않는다는 문서의 약속을 초기화 코드가 모두 지키지 못했다.

## Why
- 새 UI에 포함된 라이브러리 메뉴의 파일 쓰기 경로까지 확인하지 않았다.
- 앱과 CPU 테스트가 Context 초기화를 따로 해서 테스트가 실제 앱의 기본값을 보장하지 못했다.

## Do this instead
- 라이브러리 Demo·진단 창을 새로 노출할 때 설정 저장, 로그, 내보내기 등 기본 파일 경로와 버튼을 확인한다.
- 저장하지 않는 계약이라면 해당 경로를 공통 초기화 함수에서 명시적으로 끄고 앱과 테스트가 그 함수를 함께 사용한다.
- 파일 이름이 비활성인지 관찰하는 단언을 두고 비활성화 코드를 제거했을 때 실패하는지 확인한다.
